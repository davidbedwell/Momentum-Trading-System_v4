# MTS v2 Canonical Harmonization Audit

## Authority

`CHARTER.md` is the supreme governing document. Active architecture, standards, README, and implementation guidance must describe only current MTS v2.

Historical terminology is permitted in this audit record and Git history, not as active architecture.

## Harmonization Rule

Canonical identity, responsibility, authority, routing, dependency, workflow, and scientific meaning must not derive from:

- component numbering;
- filename;
- directory location;
- repository hierarchy;
- physical execution order;
- historical component names;
- historical filesystem organization.

## Semantic Corrections Applied

### Charter
The State of Knowledge definition was reconciled with the current governed research-state model:
- SoK is a scoped point-in-time logical view of current applicable canonical knowledge.
- unresolved contradictions/questions/hypotheses/gaps remain governed Research Nexus research state;
- those states are not automatically canonical knowledge or part of an ordinary Decision SoK.

### System Architecture
- aligned SoK with the Charter;
- replaced generic permanent contradiction storage with material active research state;
- Research Director now explicitly inspects both SoK and Active Research State.

### Engine Architecture
- removed historical engine-number commentary;
- removed repository folder layout as an architectural organization rule;
- made component identity responsibility/capability based;
- prohibited identity/routing/authority/dependency/workflow based on number, filename, directory, repository hierarchy, or physical execution order.

### Research Nexus Architecture
- removed historical Warehouse/v1 comparison language;
- converted historical migration section into current governed adoption of imported/preexisting assets;
- contradiction adoption limited to material resolution lineage satisfying retention criteria;
- source location and prior physical organization cannot define canonical semantics.

### Data Architecture
- converted v1-specific migration language into current governed data-adoption language.

### Standards
Removed historical engine numbers, Warehouse examples, v1 labels, and legacy-specific terminology from active standards while preserving current rules against noncanonical coupling and unsupported compatibility behavior.

### README
- Orchestrator replaced with Task Manager;
- orchestration wording replaced with task management;
- historical implementation comparison removed.

## Responsibility Model Confirmed

- Research Nexus: canonical durable state, semantic identity, provenance, relationships, lifecycle, retrieval.
- Task Manager: scheduling, routing, dependencies, concurrency, retries, recovery, worker supervision.
- Data Intake Engine: acquisition, normalization, deterministic measurement, intake quality/provenance, governed publication.
- Discovery Engine: empirical analysis, evidence, findings, relationships, temporal/context behavior.
- Research Director: iterative questions, Research Plans, gaps, contradictions, convergence, knowledge proposals.
- Market Discovery Engine: current-market scanning for known opportunities, anomalies, emerging or research-worthy phenomena.
- Decision Engine: action/no-action judgment using current state, applicable SoK, uncertainty, constraints, and risk.
- Learning & Governance: outcome evaluation, degradation/drift, revalidation, and governed lifecycle recommendations.
- Governance: standards, policies, contracts, schemas, authority and objective lifecycle rules.

## Residual-History Policy

Historical names and mappings belong only in:
- this audit;
- source-control history;
- deliberately preserved historical records outside active canonical definitions.

They must not be required to understand or operate current MTS v2.
