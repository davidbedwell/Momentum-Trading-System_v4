## Requirement 1: Earliest Reversal Detection Using Only PIT Observables

### Filtration and Observational Equivalence

Define the natural filtration $\mathcal{F}_n$ generated by:
$$\mathcal{F}_n = \sigma\bigl(\{p_i^{(j)}\}_{i \leq n},\ \{f_i^{(j)}\}_{i \leq n},\ \{r_i^{(j)}\}_{i \leq n-2}\bigr)$$

where $p_i^{(j)}$ is the open price of asset $j$ at session $i$, $f_i^{(j)}$ is the sensor reading (PIT-available at signal time), and $r_i^{(j)} = p_{i+2}^{(j)}(1-c/2)/(p_{i+1}^{(j)}(1+c/2)) - 1$ is the realized net return (available at session $i+3$).

**Hard 3-session limit (proved, not assumed):** For signal at session $k$, the outcome $r_k^{(j)}$ enters $\mathcal{F}_{k+3}$ and not $\mathcal{F}_{k+2}$. No function of $\mathcal{F}_{k+2}$ can distinguish the realized return at maturity $k+2$ from its conditional expectation. This is not a statistical accumulation delay—it is a definitional constraint on the filtration.

**Observational equivalence before session $k+3$:** Under the supplied DGP, the joint distribution of $(p_i^{(j)}, f_i^{(j)})_{i \leq k+2}$ is identical under stable and reversal scenarios (prices are bit-identical; sensor marginals are symmetric). Therefore no test statistic measurable with respect to $\mathcal{F}_{k+2}$ has power against the reversal alternative. This is an impossibility result, not an engineering gap.

**Statistical accumulation delay (separate from hard limit):** After session $k+3$, outcomes begin accumulating. The iteration6 cross-sectional residual contrast uses:
$$S_n^{(w)} = \frac{1}{w}\sum_{d=n-2-w}^{n-3} \left[\bar{r}_d^{(4)} - \bar{r}_d^{(0)}\right] - \left[\hat{\mu}_4 - \hat{\mu}_0\right]$$

where $\bar{r}_d^{(c)}$ is the cross-sectional mean realized return for sensor cell $c$ on date $d$, and $\hat{\mu}_c$ is the training-period cell mean. This statistic is $\mathcal{F}_n$-measurable and has power after outcomes accumulate.

### Concrete Online Sequential Algorithm

**Proposed: Mixture e-process for rapid reversal detection**

Define the cross-sectional contrast at session $n$ with window $w \in \{2, 4, 8\}$:
$$C_n^{(w)} = \frac{1}{w}\sum_{d=n-2-w}^{n-3} \left(\bar{r}_d^{(4)} - \bar{r}_d^{(0)}\right)$$

where each date $d$ requires $\geq 2$ assets in each extreme cell. The training-period estimate is $\hat{\Delta} = \hat{\mu}_4 - \hat{\mu}_0$ (fit on sessions 0–399).

**Mixture e-process (horizon-free, no prespecified number of looks):**

For each window $w$, define the running e-process:
$$E_n^{(w)} = \prod_{d \in \text{dates}(n,w)} \exp\!\left(\lambda_w \cdot \text{sign}(C_n^{(w)} - \hat{\Delta}) \cdot (C_n^{(w)} - \hat{\Delta}) - \psi(\lambda_w)\right)$$

where $\psi(\lambda) = \lambda^2 \sigma_w^2 / 2$ is the log-moment-generating function under the null (subGaussian with $\sigma_w = 0.018/\sqrt{w}$), and $\lambda_w$ is the mixture parameter. The e-process satisfies $\mathbb{E}[E_n^{(w)}] \leq 1$ under the null for all $n$, enabling anytime-valid inference without prespecifying the number of looks.

**Alarm threshold:** Raise alarm when $E_n^{(w)} \geq 1/\alpha$ for any $w$, where $\alpha = 0.01/3$ (Bonferroni over 3 windows). This controls the false-alarm probability at $\alpha = 0.01$ without requiring a prespecified scan schedule.

**Pseudocode:**

```python
class MixtureEProcessDetector:
    def __init__(self, mu_hat, sigma_base=0.018, alpha=0.01/3, windows=(2,4,8)):
        self.mu_hat = mu_hat          # training-period Delta = mu_4 - mu_0
        self.sigma_base = sigma_base  # subGaussian envelope
        self.alpha = alpha            # per-window alarm threshold
        self.windows = windows
        self.e_values = {w: 1.0 for w in windows}
        self.latched = False
        self.alarm_session = None

    def contrast(self, prices, sensors, n, w):
        """Compute cross-sectional contrast; returns None if insufficient data."""
        dates = range(n-2-w, n-2)
        contrasts = []
        for d in dates:
            cell4 = [observed(prices, d, j) for j in range(24) if sensors[d][j] == 4]
            cell0 = [observed(prices, d, j) for j in range(24) if sensors[d][j] == 0]
            if len(cell4) >= 2 and len(cell0) >= 2:
                contrasts.append(mean(cell4) - mean(cell0))
        if len(contrasts) < w:
            return None
        return mean(contrasts)

    def update(self, prices, sensors, n):
        """Update e-processes; call at each session n >= START+3."""
        if self.latched:
            return True
        for w in self.windows:
            c = self.contrast(prices, sensors, n, w)
            if c is None:
                continue
            delta = c - self.mu_hat
            sigma_w = self.sigma_base / (w ** 0.5)
            # Optimal lambda for one-sided test (reversal increases delta)
            lambda_w = delta / (sigma_w ** 2)
            lambda_w = max(0, min(lambda_w, 1.0 / sigma_w))  # clip for stability
            log_increment = lambda_w * delta - 0.5 * (lambda_w * sigma_w) ** 2
            self.e_values[w] *= math.exp(log_increment)
            if self.e_values[w] >= 1.0 / self.alpha:
                self.latched = True
                self.alarm_session = n
                return True
        return False
```

**Comparison with current 2/4/8-window gate (iteration6):**

| Property | Current (iteration6) | Proposed mixture e-process |
|---|---|---|
| False-alarm control | Fixed envelope, prespecified looks | Anytime-valid, no look budget |
| Detection delay (measured) | 4–7 sessions | Hypothesis: similar or faster |
| Multiplicity correction | Bonferroni over 3 windows × 378 looks | Bonferroni over 3 windows, any n |
| Requires prespecified horizon | Yes (126 sessions) | No |
| Power calculation | Not available (4 seeds) | Not available (4 seeds) |

**Detection delay and power under this DGP:** With 4 seeds and 126-session windows, no formal power calculation is possible. The measured delays of 4–7 sessions in iteration6 represent the empirical lower bound achievable with the current DGP. The mixture e-process hypothesis is that it achieves similar delays with stronger false-alarm guarantees. This requires ≥20 independent reversal episodes to estimate power with useful precision.

**Multiplicity correction across assets/cells/channels/time:** The current Bonferroni correction over 3 windows is appropriate for the anytime-valid e-process. Cross-asset dependence within dates is handled by using date-level means (one observation per date, not per asset). Serial dependence across dates is not modeled; the subGaussian envelope is a conservative assumption.

**False-alarm assumptions:** The 0.018 subGaussian envelope is a synthetic engineering assumption derived from the DGP parameters ($\sigma_{\text{common}} = 0.003$, $\sigma_{\text{idio}} = 0.008$). It is not a certified real-market bound. Under the null (stable scenario), the measured false-alarm rate is 0/12 paired scenario units, but 4 independent seeds give a 52.7% one-sided 95% upper bound on the seed alarm probability.

**Missing extreme-cell dates:** When fewer than 2 assets appear in a cell on a given date, that date is skipped conservatively. This reduces effective window size but maintains validity. The iteration6 implementation already handles this correctly.

## Requirement 2: Eliminate False GREAT Without Lowering Stable Return

### Finite-Sample Observation vs. Population Guarantee

**Measured fact:** Iteration6 achieves 0 false GREAT on stable scenarios across 4 seeds × 3 stable scenarios = 12 paired units. This is a finite-sample observation, not a population guarantee.

**Population guarantee impossibility:** With 4 independent seeds, the 95% one-sided upper bound on the false-GREAT rate per stable seed is $1 - 0.05^{1/4} \approx 52.7\%$. No population guarantee of ≤1% false GREAT on stable scenarios can be established from 4 seeds.

**Both demands (zero false GREAT + nonzero stable return) are mathematically achievable** in the finite-sample sense demonstrated by iteration6: stable return ≈85% (synthetic, not real alpha), false GREAT = 0 on stable. The tradeoff is:

1. **Unavoidable 3-session exposure:** During sessions $k, k+1, k+2$ after a reversal at session $k$, no PIT-observable can distinguish the reversal. The 86 false GREAT in iteration6 final results occur in these first 3–7 sessions. Reducing this requires either (a) accepting zero coverage during the exposure window, or (b) accepting some false GREAT.

2. **Funding and costs:** The 3-session exposure window costs approximately $762 in costs and −2.24% adverse return (iteration6 final, mean across 4 seeds). This is the irreducible cost of the hard PIT limit.

### Exposure/Risk Decision Policy

**Constrained objective:**
$$\max_{\pi} \mathbb{E}\left[\sum_{k=\text{START}}^{\text{END}} r_k^{\pi} \cdot \mathbf{1}[\text{label}_k \in \{\text{GOOD, GREAT}\}]\right]$$
subject to:
- $\text{FalseGREAT}_{\text{stable}} \leq \epsilon_1$ (stakeholder choice: $\epsilon_1 = 0.01$ in preregistration)
- $\text{AdverseReturn}_{\text{reversal}} \geq -\delta$ (stakeholder choice: $\delta = 0.05$ in preregistration)
- $\text{PerTradeLoss} \leq 0.02$ (hard constraint)
- $\text{Cash} \geq 0$ (hard constraint)

**Abstention/recovery logic:**

```python
class ExposurePolicy:
    def __init__(self, detector, models, max_exposure_sessions=3):
        self.detector = detector
        self.models = models
        self.max_exposure_sessions = max_exposure_sessions
        self.latch_session = None
        
    def decide(self, n, predictions, trades):
        """Returns modified predictions with UNKNOWN substituted post-alarm."""
        if self.detector.latched:
            if self.latch_session is None:
                self.latch_session = n
            # No automatic recovery: requires new disjoint evidence
            # Recovery condition (not implemented in this horizon):
            # - New independent calibration episode with ≥20 dates
            # - Fitted means consistent with new regime
            return [dict(p, label='UNKNOWN', reason='RAPID_DRIFT_ABSTAIN') 
                    for p in predictions]
        return predictions
```

**No automatic recovery** is the correct policy for a 126-session bounded horizon. Recovery requires new independent calibration evidence that is not available within the horizon. This is an engineering constraint, not a philosophical choice.

### Tradeoff Frontier

| Policy | False GREAT (reversal) | Adverse Return | Stable Return | Costs |
|---|---|---|---|---|
| Full abstention (iter4) | 0 | 0% | 0% | $0 |
| Iteration5 (22-session latch) | 442 | −10.31% | 86.66% | $26,159 |
| Iteration6 (4–7 session latch) | 86 | −2.24% | 85.04% | $25,718 |
| Zero-coverage during exposure | ~13 (unavoidable) | ~−0.5% | 85.04% | ~$25,000 |
| Impossible: zero false GREAT, nonzero coverage | — | — | — | — |

**The zero-cost guarantee is impossible:** The 3-session hard limit means any policy with nonzero coverage during the reversal window will have some false GREAT. The minimum achievable is approximately 13–22 false GREAT (the "unavoidable first 3" counts from iteration5_diagnosis.json: 9–15 per seed).

**Stakeholder risk choices required:**
1. What is the acceptable false GREAT count during the unavoidable 3-session window? (Currently: accept ~13–22, cannot be zero with nonzero coverage)
2. What is the acceptable adverse return? (Currently: ≤5% per preregistration)
3. Is automatic recovery after detection acceptable, or must it require new independent evidence?

## Requirement 3: Restore Missing AVERAGE Without Forced Labels

### Estimand Clarification

Three distinct estimands are conflated in the current architecture:

1. **Individual latent class** $z \in \{0,1,2,3,4\}$: The generative DGP class, evaluator-only, never observable. Cannot be estimated from PIT observables.

2. **Conditional mean tier** $\text{tier}(\mathbb{E}[r | \text{cell}=c])$: The tier of the expected return given sensor cell $c$. This is what the current estimator targets. The AVERAGE cell mean is $\hat{\mu}_2 \approx 0$ (measured: −0.00065 to +0.00072 across seeds).

3. **Individual realized return tier** $\text{tier}(r_k^{(j)})$: The tier of the actual one-session net return. This includes common-date and idiosyncratic shocks.

**The AVERAGE absence is a conditional mean estimand problem, not a label-forcing problem.** The AVERAGE cell mean lies within radius of the POOR/GOOD boundaries because:
- $\hat{\mu}_2 \approx 0$, which is 0.002 from both boundaries
- The radius for the AVERAGE cell is typically 0.001–0.002 (iteration5 measured: 0.00104–0.00224)
- When radius ≥ 0.002, the interval $[\hat{\mu}_2 - r, \hat{\mu}_2 + r]$ spans the POOR/AVERAGE or AVERAGE/GOOD boundary → UNKNOWN

**Center-to-boundary margin:** For seed 2098214662956861329 (iteration6), the AVERAGE cell has 0 assignments. This means $|\hat{\mu}_2| + r_2 \geq 0.002$ for all dates in the test window. The margin is:
$$\text{margin} = 0.002 - |\hat{\mu}_2| - r_2$$

When margin < 0, the interval straddles a boundary and the label is UNKNOWN. This is correct behavior.

### Training-Only Identifiable Design

**The only valid fix is more independent fit/calibration dates.** The current architecture uses 400 fit dates and 200 calibration dates. The AVERAGE cell requires:
$$r_2 < 0.002 - |\hat{\mu}_2|$$

With $|\hat{\mu}_2| \approx 0.0007$ (typical), this requires $r_2 < 0.0013$. The current radius formula:
$$r = \max(2.576 \cdot \text{SE}_{\text{train}}, |\text{bias}| + 2.576 \cdot \text{SE}_{\text{cal}})$$

With $n_{\text{train}} \approx 400$ dates and $\sigma_{\text{date}} \approx 0.003/\sqrt{24} \approx 0.0006$ (common shock divided by cross-sectional mean), $\text{SE}_{\text{train}} \approx 0.0006/\sqrt{400} = 0.00003$. This is well below 0.0013.

**But the calibration SE dominates:** With $n_{\text{cal}} \approx 200$ dates and calibration bias $|\text{bias}| \approx 0.0007$:
$$r \approx |\text{bias}| + 2.576 \cdot 0.0006/\sqrt{200} \approx 0.0007 + 0.00011 = 0.00081$$

This is below 0.0013, so the AVERAGE cell *should* be certifiable with 400/200 dates. The failure on seed 2098214662956861329 indicates that for this particular seed, either $|\hat{\mu}_2|$ is larger or the calibration bias is larger than typical.

**Independent-date/sample-size calculation:**

For the AVERAGE cell to be certifiable with probability ≥ 0.9 across seeds:
$$P\left(|\hat{\mu}_2| + 2.576 \cdot \frac{\sigma}{\sqrt{n_{\text{cal}}}} < 0.002\right) \geq 0.9$$

With $\sigma \approx 0.0006$ and requiring $|\hat{\mu}_2| < 0.001$ (which holds for most seeds):
$$n_{\text{cal}} \geq \left(\frac{2.576 \cdot 0.0006}{0.002 - 0.001}\right)^2 = \left(\frac{0.00155}{0.001}\right)^2 \approx 2.4$$

This suggests 200 calibration dates is sufficient *if* the calibration bias is small. The failure is driven by calibration bias, not calibration SE.

**Feature/model change justified:** The calibration bias $|\hat{\mu}_{\text{cal}} - \hat{\mu}_{\text{train}}|$ is the key driver. This can be reduced by:

1. **Longer training window** (engineering fix, no band change): Extend fit to 600 dates, calibration to 300 dates. This reduces both SE and bias by increasing the effective sample size. Minimum new data: 200 additional synthetic sessions with same DGP.

2. **Bias-corrected radius** (engineering fix): Replace $|\text{bias}| + 2.576 \cdot \text{SE}_{\text{cal}}$ with $2.576 \cdot \sqrt{\text{SE}_{\text{train}}^2 + \text{SE}_{\text{cal}}^2}$ when the bias is within 1 SE of zero. This is a training-only choice that does not use holdout outcomes.

3. **Wider bands** (requires new preregistration): Widening AVERAGE to ±0.4% would guarantee support but changes the economic interpretation. **Not recommended without stakeholder approval and new preregistration.**

**Calibration split design (training-only):**

```python
def fit_with_bias_correction(prices, sensors, fit_range, cal_range):
    models = []
    for c in range(5):
        train_dates = dates(prices, sensors, fit_range, c)
        cal_dates = dates(prices, sensors, cal_range, c)
        
        mu_train = mean([v for _, v in train_dates])
        mu_cal = mean([v for _, v in cal_dates])
        
        se_train = se([v for _, v in train_dates])
        se_cal = se([v for _, v in cal_dates])
        
        bias = abs(mu_cal - mu_train)
        
        # Bias-corrected radius: use pooled SE when bias is within 1 SE
        if bias < se_cal:  # bias not statistically significant
            radius = 2.576 * math.sqrt(se_train**2 + se_cal**2)
        else:
            radius = max(2.576 * se_train, bias + 2.576 * se_cal)
        
        label = infer(mu_train, radius, len(train_dates), len(cal_dates))
        models.append(dict(mean=mu_train, radius=radius, ...))
    return models
```

**Conditions under which AVERAGE support is impossible or uncertifiable:**

1. **Impossible:** When the true conditional mean $\mathbb{E}[r | \text{cell}=2]$ is within 0.002 of a boundary (i.e., $|\mathbb{E}[r | \text{cell}=2]| > 0$ and the DGP places it near ±0.002). This is a DGP property, not an estimator failure.

2. **Uncertifiable with current data:** When calibration bias exceeds $0.002 - |\hat{\mu}_2|$. This occurs when the training and calibration periods have different conditional means (e.g., due to regime variation in the DGP). With 4 seeds and 126-session windows, this cannot be ruled out.

3. **No guarantee of all classes on every random tape:** The preregistration correctly states this. With iid DGP, the probability that all 5 cells are certifiable on a given tape is strictly less than 1, and cannot be made 1 without either widening bands or increasing data.

## Requirement 4: Alternative Architecture

### Architecture Overview

The proposed architecture preserves the iteration5/6 core (DGP, sensor, bands, PIT constraint) and adds:

1. **Mixture e-process detector** (replaces fixed-schedule CUSUM)
2. **Bias-corrected radius** (reduces false UNKNOWN for AVERAGE cell)
3. **Extended fit/calibration window** (600/300 dates, requires longer synthetic history)
4. **Conformal prediction set** (replaces Gaussian interval for individual-level coverage)
5. **Structured portfolio policy** (replaces greedy tier-based allocation)

### Equations and Pseudocode

#### Fitting (training-only)

```python
FIT = range(0, 600)      # 600 fit dates
CAL = range(603, 903)    # 300 calibration dates (disjoint, embargoed)
TEST = range(906, 1032)  # 126 test dates

def fit_v2(prices, sensors):
    models = []
    for c in range(5):
        tr = dates(prices, sensors, FIT, c)
        ca = dates(prices, sensors, CAL, c)
        
        mu = mean([v for _, v in tr])
        mu_cal = mean([v for _, v in ca])
        
        se_tr = se([v for _, v in tr])
        se_ca = se([v for _, v in ca])
        bias = abs(mu_cal - mu)
        
        # Bias-corrected radius
        if bias < se_ca:  # bias not significant at 1 SE
            radius = 2.576 * math.sqrt(se_tr**2 + se_ca**2)
        else:
            radius = max(2.576 * se_tr, bias + 2.576 * se_ca)
        
        # Sensor/full disagreement threshold (99th percentile, training only)
        rows = [(prices[i][j]/prices[max(0,i-1)][j]-1, observed(prices,i,j))
                for i in FIT for j in range(24) if sensors[i][j]==c]
        center = mean([x for x,y in rows])
        slope = sum((x-center)*(y-mu) for x,y in rows) / (1 + sum((x-center)**2 for x,y in rows))
        disagreements = sorted(abs(slope*(x-center)) for x,y in rows)
        threshold = max(0.0005, disagreements[int(0.99*(len(disagreements)-1))])
        
        models.append(dict(
            mean=mu, radius=radius, slope=slope, center=center,
            threshold=threshold, ntrain=len(tr), ncal=len(ca),
            cal_bias=bias, train_dates=..., cal_dates=...
        ))
    return models
```

#### Calibration (independent, disjoint)

```python
def calibrate(prices, sensors, models, cal_range):
    """Calibration uses only CAL dates; never modifies point estimates."""
    for c, m in enumerate(models):
        ca = dates(prices, sensors, cal_range, c)
        mu_cal = mean([v for _, v in ca])
        bias = abs(mu_cal - m['mean'])
        se_ca = se([v for _, v in ca])
        
        # Widen radius if calibration reveals larger bias
        new_radius = max(m['radius'], bias + 2.576 * se_ca)
        m['radius'] = new_radius  # only widens, never narrows
        m['cal_bias'] = bias
        m['ncal'] = len(ca)
    return models
```

#### Prediction (online, PIT-causal)

```python
def predict_v2(prices, sensors, models, detector):
    states = {'candidate': [], 'ungated': []}
    
    for i in range(TEST.start, TEST.stop):
        # Update detector (anytime-valid, no look budget)
        detector.update(prices, sensors, i)
        
        row_candidate = []
        row_ungated = []
        
        for j, c in enumerate(sensors[i]):
            m = models[c]
            sensor_pred = m['mean']
            lag_return = prices[i][j]/prices[i-1][j] - 1
            full_pred = sensor_pred + m['slope'] * (lag_return - m['center'])
            
            # Radius includes sensor/full displacement
            r = m['radius'] + abs(full_pred - sensor_pred)
            
            # Identifiability check (training-only)
            identifiable = max(m['mean'] for m in models) - min(m['mean'] for m in models) > 0.003
            
            # Ungated: no detector
            lab_ungated = label(full_pred, r, m['ntrain'], m['ncal'])
            if not identifiable:
                lab_ungated = 'UNKNOWN'
            row_ungated.append(dict(mean=full_pred, radius=r, label=lab_ungated))
            
            # Candidate: with detector
            lab_candidate = lab_ungated
            reason = 'INTERVAL'
            if detector.latched:
                lab_candidate = 'UNKNOWN'
                reason = 'DRIFT_LATCH'
            elif abs(full_pred - sensor_pred) > m['threshold']:
                lab_candidate = 'UNKNOWN'
                reason = 'SENSOR_FULL_DISAGREEMENT'
            row_candidate.append(dict(mean=full_pred, radius=r, label=lab_candidate, reason=reason))
        
        states['candidate'].append(row_candidate)
        states['ungated'].append(row_ungated)
    
    return states
```

#### Monitoring (mixture e-process)

```python
def monitor_v2(prices, sensors, models, n):
    """Anytime-valid mixture e-process; no prespecified look schedule."""
    delta_hat = models[4]['mean'] - models[0]['mean']  # training-period contrast
    
    alarms = []
    for w in [2, 4, 8]:
        c = cross_sectional_contrast(prices, sensors, n, w)
        if c is None:
            continue
        
        delta = c - delta_hat
        sigma_w = 0.018 / (w ** 0.5)
        
        # Optimal lambda (clipped for numerical stability)
        lambda_w = max(0, min(delta / sigma_w**2, 1.0 / sigma_w))
        log_e = lambda_w * delta - 0.5 * (lambda_w * sigma_w)**2
        
        # Update running e-value (stored in detector state)
        # Alarm when e-value ≥ 1/alpha
        if detector.e_values[w] * math.exp(log_e) >= 1.0 / (0.01 / 3):
            alarms.append(dict(
                index=n, window=w, contrast=c, delta=delta,
                e_value=detector.e_values[w] * math.exp(log_e),
                threshold=1.0 / (0.01 / 3),
                channel='MIXTURE_E_PROCESS'
            ))
    
    return alarms
```

### New External Commitment and Validation Plan

**Preregistration requirements (before any new tape generation):**
1. Freeze all source code (engine, runner, test files)
2. Commit SHA256 hashes to a publicly timestamped service (e.g., git commit with CI timestamp)
3. Specify: fit range, calibration range, test range, band widths, detector parameters, acceptance criteria
4. Draw seeds from hardware RNG after freeze

**Episode/seed denominators:**
- Minimum 8 fresh seeds for stable false-alarm claim (gives 95% upper bound ≤ 31.5%)
- Minimum 8 fresh reversal episodes for detection delay claim
- Minimum 4 fresh seeds for five-tier support claim (current standard)

**Multiple testing correction:**
- Bonferroni over 5 tiers × 4 seeds = 20 comparisons for five-tier support
- Bonferroni over 3 windows for detector false-alarm rate
- No correction for stable return (single primary endpoint)

**Stable return noninferiority:**
- Null hypothesis: iteration7 stable return ≤ iteration6 stable return − 5%
- Rejection threshold: mean return delta > −5% across all 8 seeds
- This is a noninferiority margin, not a superiority claim

**False GREAT / detection delay metrics:**
- False GREAT: count per reversal episode, reported separately for unavoidable (sessions 0–2 post-switch) and avoidable (sessions 3+ post-switch)
- Detection delay: sessions from switch to first alarm, must be 3–8 for all episodes
- False alarm: any alarm on stable scenarios, must be 0/8 seeds

**Falsification criteria:**
- FAIL if any stable seed has false GREAT > 0
- FAIL if any reversal episode has detection delay > 8 sessions
- FAIL if any stable seed triggers alarm
- FAIL if AVERAGE support < 20 on any learnable seed
- FAIL if stable return delta vs. iteration6 < −5%

**Stop criteria (numerical thresholds):**
- Stop if false GREAT rate on stable > 1% (preregistered)
- Stop if adverse return < −5% (preregistered)
- Stop if detection delay > 8 sessions on any episode (preregistered)
- Stop if compute budget > 720 seconds or replay budget > 64

### DGP Overfitting and Model Complexity Critique

**DGP overfitting:** Each iteration's design was informed by the previous iteration's results. The band widths (±0.002, ±0.006), sensor noise parameters (σ=0.30/0.50), and detector thresholds were all chosen after observing prior results. This constitutes design-space exploration that inflates the effective false-positive rate of the overall series. The iteration6 detection delay of 4–7 sessions may be optimistic for a truly novel DGP.

**Reviewed-holdout adaptation:** Iterations 2–6 all use DGP designs informed by prior results. No iteration provides a truly fresh confirmatory test. The iteration6 fresh seeds (2098214662956861329, etc.) are fresh in the sense that their outcomes were not used to choose the design, but the DGP itself was adapted from prior work.

**Model complexity:** The current architecture (sensor cell means + lag-price slope + disagreement gate + drift detector) is appropriately simple for the available data (4 seeds, 126 sessions). Adding more complex models (e.g., neural networks, factor models) would increase overfitting risk without increasing the number of independent episodes.

**No real alpha claims:** All results are synthetic. The 85%+ returns in learnable scenarios are artifacts of the injected sensor signal and cost-grossup DGP, not evidence of real trading alpha.
